# Deep Dish — план разработки (v3)

**Имя приложения:** Deep Dish (решение В. 03.10.2026; прежде — «КалорийОК»). Репо переименован: `lichmanenko/calorieok` → `lichmanenko/deep-dish` (GitHub делает редиректы со старого имени; установленная на телефоне PWA v2 после rename не переживает обновления — принято, совместимость не нужна).

**Статус:** план v3; после закрытия открытых вопросов выпускается архитектурная спека и детальный план M0.

## Цель

Домашний трекер питания и веса для семьи В. под iPhone: быстрый ввод еды, составные блюда, честная динамика веса, адаптивная норма калорий, общий семейный каталог продуктов/блюд. Пет-проект, бюджет 0 ₽, вне корпоративной отчётности (решение В. 03.10). Итеративная разработка с помощью агентов.

1. Платформа: iOS, App Store исключён → PWA «на экран Домой». Интерфейс — русский.

4. Пользователи: семья (2–3 чел.) + «вряд ли» пара близких знакомых. Приватный круг, не публичность.

11. Алгоритм нормы: Миффлин–Сан Жеор признан В. «чепухой» в смысле точности → адаптивная норма (см. § Алгоритм).

## Что умеет v2 и что берём (инвентарь из бандла, 03.10)

v2 — дневник по дням, 4 слота приёмов пищи, 140 продуктов + одиночные «свои», норма по Миффлину с фиксированным дефицитом −400/+300, график 7 дней, экспорт XLSX (30 дней), удаление записей, PWA-офлайн. Не берём ничего, кроме базы продуктов и общей идеи PWA-дневника.

## Платформенные рамки (проверено 03.10)

- Home Screen PWA на iOS: standalone, долгоживущее хранилище (home-screen приложения исключены из 7-дневного ITP-лимита, WebKit blog 10218), push не нужен.
- HealthKit из веба недоступен. Мост — «Быстрые команды»: действие «Log Health Sample» пишет в Health и вес (Body Mass), и калории (Dietary Energy) — подтверждено 03.10. Схема: shortcut → GET/POST наш API на NAS → Health и обратно. Настройка один раз на iPhone.
- BarcodeDetector в iOS Safari нет (проверено 03.10). Сканер камерой возможен только JS-библиотекой (ZXing/html5-qrcode) — качество среднее; стартуем с поиска по названию и ручного ввода EAN, сканер — эксперимент в M3.
- Background sync нет; синк — при открытии приложения и по кнопке.
- Электроперебои на NAS: SQLite в WAL-режиме переживает внезапное отключение; контейнер с автостартом; бэкапы HBS3.

## Алгоритм нормы

MFP считает BMR той же формулой Миффлина–Сан Жеора — «точность» MFP в базе и привычке, не в формуле. Deep Dish — адаптивная норма (подход MacroFactor/Carbon):
1. Старт: Миффлин / Кэтч–МакАрдл (при известном % жира) / ручной TDEE + цель и темп (кг/нед).
2. После ≥2 недель данных: TDEE_факт ≈ среднее потребление за 14 дней + 7700 × (−тренд веса кг/день); тренд веса — регрессия за 14 дней (не сырые взвешивания).
3. Цель = TDEE_факт ± дефицит/профицит по темпу; ограничители: изменение цели ≤150 ккал/нед, пол не ниже 1,1×BMR.
4. Экран «почему такая цифра» — обязателен (доверие к приложению).

## Архитектура (0 ₽)

- **Фронт**: PWA, React + TypeScript + Vite, Tailwind, Dexie (IndexedDB) с миграциями, vite-plugin-pwa (Workbox). Mobile-first, RU, тёмная/светлая темы. Деплой GitHub Pages (репо public, бесплатно).
- **Принцип offline-first**: весь функционал работает без сети и без сервера; сервер — невидимый слой синхронизации. Первый запуск и онбординг не требуют сервера; подключение NAS — опция в настройках (URL API + токен пользователя).
- **Бэкенд**: NAS TS-264C, Container Station: один Docker-контейнер с REST API + SQLite (файл на RAID, WAL). Мультиюзер по bearer-токенам (2–5 юзеров), без регистрации: юзеры создаются вручную в простейшей админке.
- **Сеть**: Tailscale (free: 3 юзера, 100 устройств — хватает на семью; «близкие знакомые» упрутся в лимит — тогда Headscale на том же NAS, решим по факту). HTTPS через Tailscale Serve. Наружу из интернета не торчит ничего; админка QTS не выставлена.
- **Синхронизация**: push/pull при открытии и по кнопке; записи с createdAt/updatedAt, tombstone для удалений; конфликты — last-write-wins по updatedAt (семейный сценарий, редкие правки). Дневники per-user приватны; каталог продуктов/блюд общий, вклады помечены автором.
- **Внешняя база**: Open Food Facts — лениво, онлайн-поиск по EAN/названию через бесплатный API + «сохранить в каталог» (кэш попадает в локальную базу). Без выгрузки дампа. Охват RU замерим по API на M2 (ожидаю: упакованные товары хорошо, домашние блюда — нет, их закрывает база v2 + семейные рецепты).
- **MyFitnessPal миграция** (не-премиум): прямой экспорт недоступен. Пути: (а) запрос данных через privacy-центр MFP — если пришлют meal-level CSV, напишем парсер; (б) ручной перенос топ-30 любимых продуктов. Не блокер.
- **Экспорт**: полный JSON-бэкап кнопкой, CSV (еда, вес). Импорт CSV.

## План итераций

- **M0 — ядро (полностью офлайн)**: проект, дизайн-система, Dexie-схема, каталог (база v2 + свои продукты + составные блюда-рецепты), дневник с датой-временем, правка/удаление/копирование дня, поиск, профиль и норма (формула/ручная), экспорт JSON/CSV. Деплой Pages, установка на телефон. Результат: ежедневная замена v2 без всякого сервера.
- **M1 — вес и умная норма**: лог веса (+% жира), цель и темп, графики с трендом, прогноз достижения, адаптивная норма v1 с экраном «почему».
- **M2 — NAS и синк**: API + SQLite на Container Station, Tailscale, мультиюзер-синк, общий каталог, автобэкапы HBS3, OFF-интеграция (замер охвата RU → онлайн-поиск + сохранение).
- **M3 — интеграции и полировка**: мост Apple Health через Shortcuts (вес bidirectional, калории — попытка), импорт MFP-CSV (если данные придут), эксперимент: JS-сканер штрихкодов, отчёты, полировка.

## Открытые вопросы к В. (после ответов — спека + план M0)

1. Состав пользователей точно: сколько юзеров сейчас и в горизонте? (≤3 — Tailscale free; больше — Headscale на NAS.)
2. Видимость в семье: дневники строго приватны per-user (видно только своё), общий только каталог блюд? Или нужна семейная видимость дневников (например, родитель — ребёнку)?
3. Запись еды: фиксировать и время приёма пищи, и время создания записи — или достаточно одного? (Рекомендую оба: метка времени еды важна для анализа привычек, время создания — для аудита правок.)
4. Слоты приёмов пищи как в MFP (завтрак/обед/ужин/перекус, расширяемые своими) или свободный список записей? (Рекомендую слоты с возможностью добавлять свои — привычнее после MFP.)
5. Apple Health стартовать с веса в обе стороны, калории — попыткой в M3: достаточно? Или калории обязательны с первого релиза моста?
6. MyFitnessPal: послать запрос на выгрузку данных сейчас (через privacy-центр; займёт недели, результат не гарантирован) — или не тратить время и перенести руками топ продуктов?
7. Репо `deep-dish` остаётся публичным (нужен для бесплатного Pages; секретов в коде нет, токены вводятся на устройстве) — ок?

Решения по умолчанию (возражай, если нет): интерфейс только русский; единицы кг/см/ккал; здоровье-мост — только через Shortcuts, без нативной оболочки; v2-деплой не поддерживаем.
