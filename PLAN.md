# Deep Dish — план разработки (v3)

**Имя приложения:** Deep Dish (решение В. 03.10.2026; прежде — «КалорийОК»). Репо переименован: `lichmanenko/calorieok` → `lichmanenko/deep-dish` (GitHub делает редиректы со старого имени; установленная на телефоне PWA v2 после rename не переживает обновления — принято, совместимость не нужна).

**Статус:** план v4, все вопросы В. закрыты (03.10.2026). Архитектура — в `SPEC.md`. Следующий шаг: старт M0 по команде В.

## Цель

Домашний трекер питания и веса для семьи В. под iPhone: быстрый ввод еды, составные блюда, честная динамика веса, адаптивная норма калорий, общий семейный каталог продуктов/блюд. Пет-проект, бюджет 0 ₽, вне корпоративной отчётности (решение В. 03.10). Итеративная разработка с помощью агентов.

## Что умеет v2 и что берём (инвентарь из бандла, 03.10)

v2 — дневник по дням, 4 слота приёмов пищи, 140 продуктов + одиночные «свои», норма по Миффлину с фиксированным дефицитом −400/+300, график 7 дней, экспорт XLSX (30 дней), удаление записей, PWA-офлайн. Не берём ничего, кроме базы продуктов и общей идеи PWA-дневника.

## Платформенные рамки (проверено 03.10)

- Home Screen PWA на iOS: standalone, долгоживущее хранилище (home-screen приложения исключены из 7-дневного ITP-лимита, WebKit blog 10218), push не нужен.
- HealthKit из веба недоступен. Мост — «Быстрые команды»: действие «Log Health Sample» пишет в Health и вес (Body Mass), и калории (Dietary Energy) — подтверждено 03.10. Схема: shortcut → GET/POST наш API на NAS → Health и обратно. Настройка один раз на iPhone.
- BarcodeDetector в iOS Safari нет (проверено 03.10). Сканер камерой возможен только JS-библиотекой (ZXing/html5-qrcode) — качество среднее; стартуем с поиска по названию и ручного ввода EAN, сканер — эксперимент в M3.
- Background sync нет; синк — при открытии приложения и по кнопке.
- Электроперебои на NAS: SQLite в WAL-режиме переживает внезапное отключение; контейнер с автостартом; бэкапы HBS3.

## Алгоритм нормы

MFP считает BMR той же формулой Миффлина–Сан Жеора — «точность» MFP в базе и привычке, не в формуле. Deep Dish — адаптивная норма (подход MacroFactor/Carbon):
1. Старт: Миффлин / Кэтч–МакАрдл (при известном % жира) / ручной TDEE + цель и темп (кг/нед).
2. После ≥2 недель данных: TDEE_факт ≈ среднее потребление за 14 дней + 7700 × (−тренд веса кг/день); тренд веса — регрессия за 14 дней (не сырые взвешивания).
3. Цель = TDEE_факт ± дефицит/профицит по темпу; ограничители: изменение цели ≤150 ккал/нед, пол не ниже 1,1×BMR.
4. Экран «почему такая цифра» — обязателен (доверие к приложению).

## Решения В. (03–04.10.2026)

1. Сеть: **Headscale сразу** (свой координационный сервер контейнером на NAS, без лимита пользователей; цена — разовая установка CA-профиля Caddy на каждое устройство семьи).
2. Дневники **приватны per-user**; общее — только каталог продуктов/блюд.
3. В записях фиксируются **оба времени**: приёма пищи и создания записи.
4. Приёмы пищи — **расширяемые слоты** (дефолт: завтрак/обед/ужин/перекус).
5. Apple Health, однонаправленно: **вес читаем из Health** в приложение, **калории пишем в Health** из приложения. Не обязательны, можно догнать позже (M3).
6. MyFitnessPal: **миграцию исключаем** (В.: «нет чего-то очень важного, чтобы тратить время»). Свои продукты заведутся через OFF и вручную.
7. Репо `deep-dish` — **публичный** (бесплатный Pages).
8. Блюда — **модель MyFitnessPal**: продукты + рецепты (составные, с выходом) + сохранённые приёмы пищи (one-tap) + недавние/частые/избранное. Детали — `SPEC.md`.
9. v2 на телефоне В. уже удалена; **файлы v2-деплоя сносим при старте M0** (заменяются новым приложением).
10. **Гамма «Графит·сталь» (№7), иконка И4 «Кольцо нормы»** (В., 04.10). Кольцо — фирменный мотив: иконка, кольцо калорий, прогресс нормы/цели — один визуальный язык. Токены — SPEC §8.
11. **Онбординг с постановкой целей; цель опциональна** (В., 04.10): без профиля — просто дневник; с профилем без цели — норма; с целью — норма + динамика + баннеры.
12. **Время приёмов пищи**: дефолтные времена завтрака/обеда/ужина в настройках (в слот пишется автоматически); время спрашивается только для перекуса; время внесения записи — служебное, в интерфейсе не показывается (В., 04.10).
13. **Мотивационные баннеры двух типов** (В., 04.10; детали на уточнении — см. открытые вопросы): «так держать» (идём по плану/быстрее, утром до ~12:00) и «предостережение» в окне срывов (паттерн с точностью до 2 ч, 3–5 текстов на тип, оба отключаемы в настройках и закрываемы в интерфейсе).
14. **Эмодзи — сдержанно, выборочно** (В., 04.10): не больше одного на блок, только где помогает сканированию; обязательны в баннерах.

## Архитектура (0 ₽)

Полная спецификация — `SPEC.md`. Кратко:
- PWA (React+TS+Vite+Tailwind+Dexie) на GitHub Pages; offline-first: сервер — невидимый слой синхронизации, первый запуск без сервера.
- Бэкенд (M2): NAS TS-264C, контейнеры: API (FastAPI+SQLite WAL), Caddy (HTTPS, внутренний CA), Headscale, tailscaled. Доступ — только из частной сети; бэкапы HBS3.
- Синк: uuid + updatedAt + tombstone, last-write-wins; дневники приватные, каталог общий, чужое редактируется через fork.
- Внешняя база: Open Food Facts — ленивый онлайн-поиск по EAN/названию + «сохранить в каталог».
- Health-мост (M3): Shortcuts поверх NAS-API (вес: Health→приложение; калории: приложение→Health).

## План итераций

- **M0 — ядро (полностью офлайн):** дизайн-токены «Графит·сталь» + чистовая иконка И4; онбординг (приветствие → как вносить → профиль/цель, цель опциональна); Dexie-схема, каталог (база v2 + свои продукты + рецепты + сохранённые приёмы пищи по модели MFP), дневник, слоты с дефолтными временами (спрашиваем только перекус), правка/удаление/копирование дня, поиск + недавние/частые/избранное, профиль и норма (формула/ручная), экспорт JSON/CSV. Снос v2-файлов, деплой Pages, установка на телефон. Результат: ежедневная замена v2 без всякого сервера.
- **M1 — вес и умная норма**: лог веса (+% жира), цель и темп, графики с трендом, прогноз достижения, адаптивная норма v1 с экраном «почему»; мотивационные баннеры (оба типа, внутри-приложечные, тумблеры + закрытие, эмодзи).
- **M2 — NAS и синк**: Headscale + tailscaled, Caddy (внутренний CA), API (FastAPI+SQLite), мультиюзер-синк, общий каталог с fork, автобэкапы HBS3, OFF-интеграция (замер охвата RU → онлайн-поиск + сохранение).
- **M3 — интеграции и полировка**: Health-мост через Shortcuts (вес из Health; калории в Health), Web Push для баннеров (если В. подтвердит — вопрос №1), эксперимент: JS-сканер штрихкодов, отчёты, полировка UX.

## Открытые вопросы (к В., 04.10)

1. **Баннеры — только внутри приложения или всё же пуши?** Если сообщение об окне срывов должно приходить, когда приложение закрыто, — это Web Push (сервер M2 + iOS 16.4+, реализация M3). Если достаточно «показать при ближайшем открытии в окне» — дешевле и раньше (M1). Рекомендую начать с внутри-приложечных, пуш решить по живому использованию.
2. **Часовой пояс утреннего баннера** — часовая зона устройства или строго московское время? (Рекомендую зону устройства: в поездках логика сохраняется.)
3. **Тон предостережений**: пример В. «Y кг сами к тебе не придут — нужно немного потерпеть» — прямой, почти дерзкий. Такой и оставляем (3–5 вариантов в этом тоне), или половину сдержаннее?
4. **Определение «срыва»** для паттерна: предлагаю дефолт — превышение дневной нормы >20% ИЛИ приём из категорий «Сладкое / Фастфуд / Снеки / Алкоголь» во второй половине дня. Категории-триггеры настраиваются? (Рекомендую: фикс-дефолт + поле «свои категории» потом.)
