# КалорийОК — план разработки (v3)

**Статус:** план v0 на обсуждении с В. (03.10.2026). v2 остаётся задеплоенной без изменений, пока v3 не догонит и не обгонит её по пользе.

## Цель

Личный трекер питания и веса для В. под iPhone: быстрый ввод еды, честная динамика веса, умная норма калорий, данные всегда выгружаемы. Пет-проект — вне корпоративной отчётности (решение В. 03.10). Итеративная разработка с помощью агентов.

## Вводные от В. (03.10)

- Платформа: iOS, в App Store не публикуем → PWA, ставится на экран «Домой».
- UX и данные v2 не наследуем (дизайн «не очень», совместимость не нужна). База продуктов v2 — наследуем (актив).
- Референс: MyFitnessPal. Импорт данных оттуда — желателен.
- Требования: блюда (в т.ч. свои), дата-время внесения, правка внесённого, цели по весу и динамика, экспорт данных, по возможности Apple Health, хранение — на усмотрение агента (не обязательно на телефоне).
- Алгоритм нормы: Миффлин–Сан Жеор признан неточным, wants «существенно точнее» (см. § Алгоритм).

## Что умеет v2 (инвентарь из бандла, 03.10)

ЕСТЬ:
- Онбординг: пол/возраст/рост/вес, цель (дефицит −400 / поддержание / профицит +300), активность 5 уровней, расчёт нормы по Миффлину–Сан Жеору.
- Дневник: приёмы пищи (завтрак/обед/ужин/перекус) по дням, поиск по базе, вес порции в граммах, КБЖУ-итоги.
- База: 140 RU-продуктов в 21 категории (извлечена в `data/products_v2.json`) + свои продукты (одиночные, с валидацией КБЖУ).
- История 30 дней, график калорий за 7 дней, статусы «в норме/превышено».
- Экспорт XLSX за 30 дней. Удаление записей. Сброс всех данных.
- PWA: офлайн (Service Worker), standalone, safe-area.

НЕТ (против требований В.):
- Составных блюд/рецептов (только одиночные продукты).
- Времени внесения записи (только дата) и правки записи (только удаление).
- Лога веса, цели по весу, динамики и прогноза (вес только в профиле).
- Экспорта полного (JSON/CSV), импорта откуда-либо.
- Синхронизации/бэкапа (всё только в IndexedDB телефона).
- Apple Health.
- Адаптивной нормы (формула статичная, пересчёт только при смене профиля).

## Платформенные рамки (iOS PWA, проверено 03.10)

- «На экран Домой» = полноценное standalone-приложение: иконка, без браузерной обвязки.
- Хранилище: для home-screen PWA НЕ действует 7-дневный лимит ITP на script-writable storage (WebKit, блог 10218) — данные живут долго; но local-first + серверный бэкап всё равно обязательны.
- Push-уведомления и бейджи: поддерживаются с iOS 16.4+ для установленных на Домой PWA.
- HealthKit из веба недоступен принципиально (нет WebKit API). Реальный мост — приложение «Быстрые команды» (Shortcuts): GET нашего API → «Записать образец здоровья» (вес → Health); и обратный shortcut: «Найти образцы здоровья» → POST в наше API. Полуавтомат, настройка один раз.
- Background sync в WebKit нет: синхронизация при открытии приложения. Для single-user это ок.
- Обновление: Service Worker с явным «доступна новая версия» (v2 этим страдал — кэш мог залипать).

## Алгоритм нормы (критический разбор)

Факт: MyFitnessPal сам считает BMR по Миффлину–Сан Жеору (+ множитель активности + фиксированный дефицит по цели). «Точность» MFP — не в формуле, а в базе продуктов и поправках на упражнений.

Предложение v3 — адаптивная норма (подход MacroFactor/Carbon):
1. Старт: норма из формулы на выбор (Миффлин–Сан Жеор / Кэтч–МакАрдл при известном % жира / ручной TDEE) + цель и темп.
2. Через 2–3 недели накопленных данных включается коррекция по энергобалансу: TDEE_факт ≈ среднее потребление за 14 дней + 7700 × (−тренд веса, кг/день); тренд веса — линейная регрессия/EMA за 14 дней, а не сырые взвешивания.
3. Цель = TDEE_факт ± дефицит/профицит от темпа цели (1 кг жира ≈ 7700 ккал). Ограничители: изменение цели ≤ 100–150 ккал/нед, пол не ниже ~1,1×BMR.
Это и есть «существенно точнее» статических формул — норма учитывает личный метаболизм по факту, а не популяционные средние.

## Продуктовое предложение v3

- Дневник: записи с датой И временем создания/изменения (createdAt/updatedAt), правка и удаление любой записи, копирование вчерашнего дня, избранное и недавние для ввода в 2 тапа.
- Блюда: свои продукты И составные блюда-рецепты (из продуктов с граммовками, КБЖУ считается автоматически), порции.
- Вес: ежедневный лог (вес, опц. % жира), цель по весу и темп (кг/нед), график динамики с тренд-линией, прогноз достижения цели.
- Норма: адаптивная (см. § Алгоритм), с экраном «почему такая цифра».
- Экспорт/импорт: полный JSON-бэкап (одной кнопкой), CSV (еда/вес) для Excel и ручного заноса в Health, импорт CSV из MyFitnessPal.
- Apple Health: мост через Shortcuts (вес в обе стороны), без App Store.
- Напоминания: push «запиши приём пищи» (по времени, настраиваемо) — iOS 16.4+, после установки на Домой.
- Данные: local-first, автосинхронизация на сервер при открытии, автобэкапы на сервере.

## Архитектура

- Фронт: React + TypeScript + Vite, Tailwind, Dexie (IndexedDB) с миграциями, vite-plugin-pwa (workbox). Мобильный-first, RU, тёмная/светлая темы. Деплой: GitHub Pages (как v2, из корня main).
- Данные: local-first; единая модель записей с updatedAt и soft-delete → серверная реплика.
- Сервер (этап M2): крошечный REST + SQLite, single-user (bearer-токен), синхронизация last-write-wins по updatedAt (один пользователь, конфликтов практически нет). Деплой — рекомендация: Yandex Cloud serverless (оплата из РФ, предсказуемая доступность); альтернатива — Cloudflare Workers+D1 (бесплатно, риск: доступность из РФ и оплата). Переносимо между ними одним контейнером.
- Безопасность: HTTPS, bearer-токен, никаких персональных данных кроме еды/веса.

## План итераций

- **M0 — ядро (дневник):** скелет проекта, дизайн-система, Dexie, продукты (база v2 + свои), приёмы пищи с датой-временем, правка/удаление, поиск, профиль и норма (формула/ручная), PWA на Домой, деплой Pages. Результат: v3 можно пользоваться ежедневно.
- **M1 — вес и умная норма:** лог веса, цели и темп, графики с трендом, прогноз, адаптивная норма v1, экспорт JSON/CSV.
- **M2 — сервер и надёжность:** бэкенд + синхронизация + автобэкапы, push-напоминания, обновление PWA без залипания кэша.
- **M3 — интеграции:** импорт из MyFitnessPal (CSV), мост Apple Health через Shortcuts, отчёты/полировка.
