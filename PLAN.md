# КалорийОК — план разработки (v3)

**Статус:** план v1, на обсуждении с В. (03.10.2026). v2 остаётся задеплоенной без изменений, пока v3 не догонит её по пользе.

## Цель

Личный трекер питания и веса для В. под iPhone: быстрый ввод еды, честная динамика веса, умная норма калорий, данные всегда выгружаемы. Пет-проект — вне корпоративной отчётности (В. 03.10). Итеративная разработка с помощью агентов.

- Платформа: iOS, в App Store не публикуем → PWA, ставится на экран «Домой».
- **Бюджет: 0 ₽, никаких вложений** (уточнение В., 03.10). Все сервисы — только бесплатные; выбор инфраструктуры сделан с учётом доступности из РФ.
- UX и данные v2 не наследуем. База продуктов v2 (140 позиций) — наследуем, извлечена в `data/products_v2.json`.

- Требования: блюда (в т.ч. свои составные), дата-время внесения, правка внесённого, цели по весу и динамика, экспорт, Apple Health (через мост), большая внешняя база продуктов с импортом и обменом дополнениями между пользователями.

## Что умеет v2 (инвентарь из бандла, 03.10)

ЕСТЬ: онбординг (пол/возраст/рост/вес, цель −400/0/+300 ккал, активность 5 уровней), норма по Миффлину–Сан Жеору; дневник по дням (завтрак/обед/ужин/перекус), поиск, вес порции; 140 продуктов в 21 категории + одиночные свои продукты; история 30 дней, график калорий 7 дней; экспорт XLSX (30 дней); удаление записей; PWA-офлайн.

## Платформенные рамки (iOS PWA, проверено 03.10)

- «На экран Домой» = standalone-приложение; для home-screen PWA не действует 7-дневный лимит ITP на хранилище (WebKit blog 10218). Local-first + бэкап всё равно обязательны.
- Push-уведомления — iOS 16.4+ для установленных PWA. Без своего сервера напоминания реализуемы через ntfy.sh (уже используется в окружении В.) либо откладываются.
- HealthKit из веба недоступен; мост — «Быстрые команды» (Shortcuts): GET последнего веса из нашего хранилища → «Записать образец здоровья»; обратный shortcut читает вес из Health и отправляет POST. Настройка один раз, без App Store.
- Background sync в WebKit нет — синхронизация при открытии приложения (для single-user достаточно).
- Сканирование штрихкодов камерой в iOS Safari работает плохо (нет BarcodeDetector) — поиск по названию и ручной ввод кода, сканер не обещаем.

## Алгоритм нормы

MyFitnessPal изнутри использует ту же формулу Миффлина–Сан Жеора + множитель активности + фиксированный дефицит; его «точность» — в базе, не в формуле. Формула в принципе популяционное среднее. В v3 — адаптивная норма (подход MacroFactor/Carbon):
1. Старт: формула на выбор (Миффлин–Сан Жеор / Кэтч–МакАрдл при известном % жира / ручной TDEE) + цель и темп.
2. После 2–3 недель данных — коррекция по энергобалансу: TDEE_факт ≈ среднее потребление за 14 дней + 7700 × (−тренд веса, кг/день); тренд — регрессия/EMA за 14 дней.
3. Цель = TDEE_факт ± дефицит/профицит по темпу (1 кг жира ≈ 7700 ккал); ограничители: ≤ 100–150 ккал/нед изменения, пол не ниже ~1,1×BMR.
Экран «почему такая цифра» обязателен.

## Архитектура (при бюджете 0 ₽)

- Фронт: React + TypeScript + Vite, Tailwind, Dexie (IndexedDB), vite-plugin-pwa. Мобильный-first, RU, тёмная/светлая темы. Деплой: GitHub Pages из корня main (как v2) — бесплатно.
- Данные: local-first; единая модель с createdAt/updatedAt и soft-delete.
- **Бэкенд: NAS QNAP TS-264C** (решение В. 03.10, железо уже есть, 0 ₽): в Container Station крошечный REST API (Docker) + SQLite, single-user/семейный (bearer-токен), SQLite-файл на RAID, ежедневные копии через Hybrid Backup Sync. Доступ с телефона — Tailscale (бесплатно, WireGuard, работает из РФ без белого IP; HTTPS через Tailscale Serve). Если NAS недоступен — приложение живёт на локальных данных и досинхронизируется позже.
  - Альтернатива, если NAS-путь не зайдёт: GitHub как бэкенд (приватный репо с JSON-коммитами через REST API, 0 ₽, стабильно из РФ) или Supabase free tier (риск: чужая платформа, доступность из РФ).
- Общая база продуктов: если участники — семья/близкие, живёт на NAS-API (участники приглашаются в Tailscale-сеть). Для публичного обмена — GitHub-репо `calorieok-data` с JSON-базой (вклад коммитом/PR, валидация КБЖУ по 4/4/9).
- Внешняя база (источник): **Open Food Facts** — открытая (ODbL), есть RU-продукты, штрихкоды, дампы CSV для одноразового импорта и бесплатный API. Импорт: RU-подмножество скриптом → очистка → дополнение базы. Атрибуция OFF — в «О приложении».
- Экспорт/импорт: полный JSON-бэкап кнопкой; CSV (еда/вес); импорт CSV из MyFitnessPal.
- Безопасность: наружу выставляется только API-эндпоинт с токеном (админка QTS в интернет не торчит), HTTPS, PAT/токены — локально на устройствах.

## План итераций

- **M0 — ядро (дневник):** скелет проекта, дизайн-система, Dexie, продукты (база v2 + свои продукты), приёмы пищи с датой-временем, правка/удаление/копирование дня, поиск, профиль и норма (формула/ручная), PWA на Домой, деплой Pages. Результат: v3 можно пользоваться ежедневно.
- **M1 — вес и умная норма:** лог веса, цели и темп, графики с трендом, прогноз, адаптивная норма v1, экспорт JSON/CSV.
- **M2 — данные и обмен:** бэкенд на NAS (Docker API + SQLite, Tailscale-доступ), синк/бэкапы, общая база продуктов, импорт из Open Food Facts (RU-выгрузка), импорт CSV из MyFitnessPal.
- **M3 — интеграции и полировка:** мост Apple Health через Shortcuts, push/ntfy-напоминания (если нужны), отчёты, тёмная тема, полировка UX.
